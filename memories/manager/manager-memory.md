### Stages and intermediate contracts

1. **Inventory / input gate.** Validate required headers, unique IDs, timestamps, known policy actions, manifest path containment (resolve under dataset, reject traversal/symlink escape), file existence and hash snapshot. Build one run metadata object containing run_id, input/code/prompt/model fingerprints and later output hash. Failure is explicit, not an empty result.
2. **Intent.** Input is `(case_id, request_text)` only, without reported_status, family hints, sample labels or case-number semantics. AI returns `{case_id, authorizes_deletion: bool, supporting_quote: str, ambiguity: str|null}`. Quote must occur in the supplied request. Mixed/negated requests are evaluated semantically. Ambiguity requires review/retry; do not default to deletion. Unauthorized cases bypass deletion planning entirely.
3. **Identity timeline / candidate links.** Input is supplied email, audit_at and eligible identity/history/catalog facts. Output is stable subject ID plus typed aliases with raw value, safe normalized form, validity/observation time and source ID. Preserve old/new values, known historical aliases and exact resource/business-key links. Normalize email case consistently; keep dots/plus aliases distinct. Normalize phone formatting without inventing country codes; hash matches exact normalized hex, with any computed hash supported by a verified convention. Name alone is retrieval, not conclusive ownership. No ID-number arithmetic. Ambiguous identifiers require corroboration.
4. **Evidence extraction (parse once).** Deterministic adapters handle known JSON shapes, typed/embedded-JSON SQL tables, pipe text and log dialects. Join start/completion by service+trace and preserve all contributing lines. Use `pdftotext -layout` for PDFs, Tesseract for screenshots; AI interprets document content and resolves structured business facts, with image/page attachment only after runtime support is tested. Preserve collection/table/replica, snapshot scope, row timestamps, actual field values and source positions. Separate extraction from case-specific filtering. SQL execution, if used, is only in disposable memory, extension loading disabled, no ATTACH or filesystem/extension-capable statements; validate/restrict input SQL or install an authorizer and verify transaction handling. Never execute SQL against supplied/live databases.
5. **Timestamped fact store.** Plain immutable records/list indexes are sufficient. Each fact has internal fact_id, evidence_id, source path + location, claim_kind (`observation`, `activity_claim`, `identity_link`, `scope`), system_id, resource_id, category if grounded, subject keys, payload, event/observed_at, manifest captured_at, snapshot/export time and scope/replica. Missing versus explicit null/blank must remain distinct. Artifact extraction errors have their own diagnostics, not absent facts. All files receive success/failure and extracted-record counts.
6. **Case reconstruction.** Filter both observations and links by audit_at; require available_at/capture and applicable observation/snapshot times <= cutoff. Group actual observations by resource+copy, not only service. Use content-backed links to find already-anonymized/absent resources. Expand through relevant activity/resource/flow links to a fixed point; do not stop after first hit. Closed, eligible collection snapshots may establish absence for a previously grounded resource in that exact collection/copy; missing table scope or unmatched text cannot. Compare primary and every included replica. Reduce actual state in chronological order within scope; retain conflicting facts and reasons. A newer SUCCESS alone cannot erase an observed violation. Pre-request evidence is not automatically irrelevant; trace it to subsequent eligible state evidence rather than applying an arbitrary request-time window.
7. **Policy + plan.** Input: resolved resource states, ownership, category/conditions, retention facts and dependency edges. Output: internal decision plus finding/repair/final-check tuples with supporting fact IDs. Read rules instead of hardcoding case patterns. DELETE categories => absent; REDACT => permitted retained record without prohibited direct identifiers; ANONYMIZE => no reversible subject linkage; RETAIN => required record remains. DATA_FLOW active and unsafe restore risk follow PS completeness requirements even though DATA_FLOW is not a policy CSV category. A stable tombstone user_id is allowed, not a reason to anonymize/delete it. Retained archive restore blocking is its own obligation; do not delete the archive.
8. **Serialization + finalization.** Deterministically map to exact allowed tuples, deduplicate identical logical checks, sort, number, validate, and CSV-write atomically only if every target case is defensible and all mandatory invariants pass. Keep rationale/uncertainty/provenance locations outside steps_json. On failure exit nonzero, identify affected cases; leave any existing completed output untouched and do not report a successful full run.

Internal `Decision` contract: `(case_id, authorized, resources, violations, required_final_checks, diagnostics)`. Output status follows facts, not model free text: unauthorized => NOT_APPLICABLE/[]; authorized with supported violations => INCOMPLETE with all findings, necessary repairs, whole required final-state checks; authorized with evidence-established compliant state => COMPLETE and cited verification only. Unknown category/retention condition or unresolved essential fact blocks finalization; it is not an extra submission status.
